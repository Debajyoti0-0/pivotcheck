# Code of Conduct

## Our standard

PivotCheck is a security-assessment tool built around an evidence-first,
safety-first philosophy. Everyone participating in this project — in
issues, pull requests, discussions, documentation, or packaging — is
expected to interact professionally and in good faith.

## Expected behavior

- Be technical, precise, and kind. Critique ideas and evidence, not people.
- Respect that security work happens in many contexts and jurisdictions;
  assume legitimate, authorized use unless demonstrated otherwise.
- Report defects with reproducible evidence; do not speculate about
  maintainers, users, or organizations.
- Never share credential material, exploit payloads, or customer data in
  any public channel. Redact sensitive information before submitting.

## Unacceptable behavior

- Harassment, discrimination, or personal attacks of any kind.
- Posting malware, credential dumps, private data, or unredacted
  engagement material.
- Fabricating test results, operator reports, or adoption claims.
- Deliberately misrepresenting what the tool does or its safety model.

## Reporting

Report conduct issues through the private channel described in
[SECURITY.md](SECURITY.md) (private vulnerability reporting). Conduct
reports are handled by the repository maintainers with discretion; no
public discussion of individual reports.

## Scope

This policy applies to all project spaces (repository, issue tracker,
discussions, pull requests) and to any space representing the project.

## Attribution

This document adapts general community-conduct conventions to the
specifics of a security tool. It may evolve via normal pull requests.
